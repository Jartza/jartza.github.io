The display is an ST7032i, so the character shapes live in the display controller rather than in the firmware, and which ROM variant it is was never written down. This table was read off a real badge with a camera by the infr/tagsu project (write-up), and it agrees with every check that can be made from this side.

All six codes the original editor translated land exactly where it put them (ä 0x84, å 0x86, Ä 0x8E, Å 0x8F, ö 0x94, Ö 0x99). 0xFB and 0xFC are « and », which is what the firmware draws either side of the selected menu item. And 0xA0–0xDF is the HD44780 A00 katakana block, unchanged.

Two things to watch for, both normal for this family of controller: 0x5C shows ¥ rather than a backslash, and 0x7E/0x7F are → and ←. Codes whose character is missing from the display font are left out, because the editor could not preview them.

Checking it against a real Tagsu

The probe builds 14 screens, one per block of 16 codes, each showing the codes on the top row and which block it is underneath. Send it to a tag and photograph the screens to confirm the table above on your own hardware; any correction goes in js/charmap.js.
